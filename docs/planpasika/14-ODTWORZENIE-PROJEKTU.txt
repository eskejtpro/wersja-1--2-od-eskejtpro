ODTWORZENIE LOKALNE (WINDOWS 10/11 x64)
1. Zainstaluj Git, Node.js zgodny z `package.json` (`engines`), JDK 21, Android SDK Platform/Build Tools i Platform Tools. Zweryfikuj lokalne wersje i ścieżki.
2. Sklonuj prywatne repozytorium i wybierz `codex/planpasika-release` lub jawnie wskazaną nowszą gałąź integracyjną. Zapisz `git status`, `git rev-parse HEAD`; nie nadpisuj istniejącego dirty checkoutu.
3. W root uruchom `npm ci`, `npm run lint`, `npm test`, `npm run test:server`, `npm run test:cloud`, `npm run test:ai-transport`, `npm run test:ops-agent`, a następnie `npm run build`. Testy mocków nie są produkcyjnym E2E.
4. Dla Androida uruchom `npx cap sync android`. Ustaw własne `android/local.properties` lokalnie; nie commituj go. Zweryfikuj JDK/SDK na tym komputerze.
5. W `android` uruchom `gradlew.bat testDebugUnitTest assembleDebug assembleDebugAndroidTest`. AndroidTest APK może się zbudować bez uruchomienia testu; wykonanie wymaga urządzenia/emulatora.
6. Sprawdź APK: `applicationId=com.gymtracker.pro`, versionName/code, SDK, uprawnienia, podpis i SHA-256. Kandydat instalacji aktualizacyjnej musi mieć zgodny certyfikat; użyj `scripts/install-android-candidate.ps1`, który ma odmawiać przy rozbieżności. Nie odinstalowuj aplikacji ani nie czyść danych, by ominąć podpis.
7. Podłącz telefon, włącz USB debugging, zaakceptuj autoryzację, następnie `adb devices -l`. Dopiero po rozpoznaniu modelu/serialu wykonuj install `-r`, launch, logcat i testy. Brak urządzenia = BLOCKED/UNKNOWN.

- `npm ci` korzysta z lockfile; nie aktualizuj zależności przy samym odtworzeniu.
- Nigdy nie commituj `.env`, OAuth credentials, Bearer/Google ID tokens, klucza Gemini ani service-account files. Przed push uruchom security scan.
